12Digital dice with two 7-segment displays

Real parts Press a button: the two displays spin through random numbers, slow down and stop on two dice values, like rolling two real dice. It uses two Kingbright SC39-11SURKWA displays (see Using real parts), an Arduino and the multiplexing trick: both displays share the same 8 segment wires, and two transistors switch them on one at a time, very fast.

Mode:

Tick slow-motion multiplexing to see the secret: only one display is ever lit at a time. The Arduino swaps between them every 4 ms, which is far too fast for your eye.

Schematic

Arduino pinGoes to
D2 … D9Through a 330 Ω resistor each, to segments a b c d e f g dp, i.e. display pins 7 6 4 2 1 9 10 5. Wire the same pin of both displays together.
D10, D11Through 1 kΩ to the base of BC547 #1 / #2. Each collector goes to the COM (pin 3 or 8) of display 1 / 2, and each emitter to GND.
D12Push button to GND (the code turns on the internal pull-up, so no resistor is needed).
A0Leave it unconnected: its random noise seeds the random-number generator.

Arduino code

// Digital dice: 2 × Kingbright SC39-11SURKWA (common cathode), multiplexed
const byte SEG[8]   = {2, 3, 4, 5, 6, 7, 8, 9};  // a b c d e f g dp (each via 330 Ω)
const byte DIGIT[2] = {10, 11};                  // → 1 kΩ → BC547 base, collector = display COM
const byte BUTTON   = 12;                        // push button to GND
const byte FONT[10] = {0x3F,0x06,0x5B,0x4F,0x66,0x6D,0x7D,0x07,0x7F,0x6F}; // bit0 = a … bit6 = g
byte value[2] = {6, 6};

void showDigit(byte d, byte n) {
  for (byte s = 0; s < 8; s++) digitalWrite(SEG[s], bitRead(FONT[n], s));
  digitalWrite(DIGIT[d], HIGH);    // transistor ON → this display lights
  delay(4);
  digitalWrite(DIGIT[d], LOW);     // OFF before changing the segments (no "ghosting")
}

void refresh(unsigned long ms) {   // keep both displays lit for ms milliseconds
  unsigned long start = millis();
  while (millis() - start < ms) { showDigit(0, value[0]); showDigit(1, value[1]); }
}

void setup() {
  for (byte s = 0; s < 8; s++) pinMode(SEG[s], OUTPUT);
  for (byte d = 0; d < 2; d++) pinMode(DIGIT[d], OUTPUT);
  pinMode(BUTTON, INPUT_PULLUP);
  randomSeed(analogRead(A0));      // unconnected pin = random noise
}

void loop() {
  if (digitalRead(BUTTON) == LOW) {                 // button pressed: roll!
    for (int wait = 20; wait < 260; wait += 15) {   // spins fast, then slows down
      value[0] = random(1, 7);                      // 1 … 6
      value[1] = random(1, 7);
      refresh(wait);
    }
  }
  refresh(20);
}

🧰 You need

  • 2 × Kingbright SC39-11SURKWA (Gotronic 03099)
  • Arduino Uno or compatible (e.g. Joy-It ONE-C)
  • 8 × 330 Ω (segments), 2 × 1 kΩ (bases)
  • 2 × BC547B transistors
  • 1 push button, breadboard + jumper wires

🔧 Build

  1. Place both displays across the breadboard gap, side by side.
  2. Link the same pins of both displays together (7↔7, 6↔6, … 5↔5), except COM.
  3. Each shared segment line → 330 Ω → Arduino D2–D9.
  4. Each COM → its own BC547 collector. Emitters → GND, bases → 1 kΩ → D10 / D11.
  5. Button between D12 and GND. Upload the code and press!

🧪 Variants to try

Change delay(4) to delay(200)You see the displays take turns: multiplexing in slow motion.
One die only: set value[0] to blankAdd a blank code to FONT (0x00) and show it on display 1.
A 2–12 roll: show value[0] + value[1] on both digitsTens on the left, units on the right: a "two-dice total" display.
Light the decimal point while rollingSet bit 7 (dp) in the FONT value during the animation.
220 Ω instead of 330 ΩBrighter. Each digit is only on half the time, so short peaks of ~14 mA are fine (the datasheet allows 185 mA pulses).
Remove the transistors and drive COM straight from D10/D11Dimmer and risky: one pin would sink up to 8 segments × 9 mA = 72 mA, way over the ~20–40 mA an Arduino pin can handle.
Going further, without Arduino555 clock (fast while the button is held) → CD4510 counter → CD4511 decoder → display. A great challenge using the chips from the Microchips page.
